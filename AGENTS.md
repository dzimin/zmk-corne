# Правила проекта Corne

## Общение

- Отвечай по-русски, кратко и понятно, без избыточного оформления
- Указывай уверенность от 1 до 10; при оценке ниже 8 предлагай допроверку
- Элементы списков не завершай точкой
- Для YQL-запросов используй субагентов

## Git и сохранность работы

- Перед правками проверяй текущую ветку, `git status` и пользовательские изменения
- Работай в ветках `codex/*`, сохраняй законченные изменения отдельными коммитами и переноси их в `master` через pull request
- Исходная точка: тег `baseline-2026-10-23`, коммит `390fbc25b4e6bd9492558a2125c9812a5fbf78b4`
- Не перемещай и не удаляй исходный тег и исходный GitHub Release
- Не переписывай опубликованную историю; отменяй опубликованные изменения новыми коммитами `git revert`
- Не выполняй разрушительные операции, включая `reset --hard`, `clean -fd`, принудительную отправку и удаление пользовательских правок, без явного запроса пользователя
- Не включай в коммиты посторонние файлы, дампы устройств, резервные копии и результаты сборки; заводские дампы храни только в игнорируемой папке `backups/`
- Перед коммитом проверяй индекс; не используй безусловный `git add .`

## Прошивка

- Единственный источник раскладки — `config/corne.keymap`; не дублируй слои, сочетания и макросы для приёмника
- Поддерживай обычную схему с центральной левой половинкой и схему с отдельным приёмником, где обе половинки периферийные
- Различия ролей, экрана и питания задавай отдельными профилями и параметрами сборки
- На центральных устройствах сохраняй USB и Bluetooth со штатным выбором выхода ZMK; не добавляй кнопки USB/Bluetooth или собственную автоматику без запроса пользователя
- Сохраняй существующие кнопки выбора Bluetooth-профилей и очистки сопряжения
- Сохраняй ZMK `v0.2`; внешние модули закрепляй конкретным коммитом, изменения зависимостей оформляй явно
- Настройки дисплея и питания приёмника не должны попадать в сборки половинок
- Цель `nice_nano_v2` для приёмника предварительная: до прошивки требуется подтвердить аппаратную совместимость
- Не прошивай устройства и не сбрасывай сопряжения автоматически; сборка прошивки не означает разрешение на изменение устройства

## Проверки и документация

- После изменений общей раскладки, конфигурации или зависимостей проверяй обе схемы и все цели `build.yaml`
- Проверяй итоговые Kconfig и devicetree: роли, число периферий, USB/Bluetooth, матрицу, дисплей и питание
- При изменении файлов прошивки или порядка восстановления обновляй README
- Различай «собрано в CI» и «проверено на устройствах»; не объявляй непроведённые проверки успешными
- В отчёте отмечай проверки экрана, сопряжения, работы от зарядки и отката как отдельные аппаратные проверки
- Готовые проверенные сборкой комплекты сохраняй в GitHub Releases с контрольными суммами и идентификатором исходного коммита; аппаратный статус указывай явно
